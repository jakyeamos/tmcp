Post-edit protocol:

- Re-run blind evaluations for all three release-critical cases, not only B.
- Use one fresh, context-free runner per case per run. Each runner sees only its case input and the target skill—never the bar, smells, other cases, or expected output.
- After each run, sweep the live checkout for leaked changes and clean them.
- Have a separate fresh judge grade each artifact using only the artifact, that case’s bar, and the skill’s first principles, citing specific evidence for every verdict.
- Because all cases are release-critical, repeat each blind run 2–3 times and report pass rates.

The B fix can be claimed effective only if the post-edit B runs consistently clear its bar at the required rate, with judge verdicts grounded in specific artifact evidence. A single B pass is insufficient, and B’s improvement does not establish that the edit is releasable unless A and C also retain acceptable pass rates.

A’s new miss is a regression finding. Before revising again, diagnose it as either:

- a skill defect introduced or exposed by the B edit, mapped to a `write-skills` failure mode; or
- a bad case/bar that asks for inappropriate or inexpressible behavior or penalizes a defensible judgment.

Do not immediately alter the skill to make A pass. First confirm the miss through repeated blind runs if it is borderline, examine cited evidence against A’s bar and the skill’s first principles, and defend the classification. If it is a genuine skill regression, make the smallest revision targeted to that named defect, following `write-skills`, then re-evaluate A, B, and C again. If A’s bar is wrong, correct or reject the case rather than encoding the wrong behavior. No release claim is justified until the complete sweep clears the rate bar for every valid case.

# Conditional `Workflow` micro-ablation protocol

**Status: not run.** The full-section campaign remains held on per-fixture
intact-control reliability, so launching a second runner campaign now would
over-interpret a relative effect before the baseline is reliable.

If a new campaign is justified after a fresh, predeclared control-reliability
baseline, it must test one independently named workflow step at a time against
the full intact skill, with all other workflow steps unchanged:

1. input validation, first principles, and judgment/conformance mode;
2. blind isolated run plus the live-checkout sweep;
3. separate evidence-based judgment;
4. repeated runs and pass-rate reporting;
5. skill-defect versus bad-case diagnosis;
6. revision constrained by `write-skills`; and
7. all-case regression re-evaluation.

Each intervention needs its own fixtures, behavior contract, expected effect
direction, runner blinding, fresh judges, 2+ repetitions, 6+ fixtures across
3+ configurations, the fixture-block analysis policy, and both control floors
declared before the first runner call. A list-item micro-ablation must not be
claimed from the current top-level-section ablation engine: it requires a new
attachment representation that can prove every non-target step is byte-stable.

The near-term repair target is baseline reliability, especially regression
retest and failure diagnosis—not a broad rewrite of the `Workflow` section.

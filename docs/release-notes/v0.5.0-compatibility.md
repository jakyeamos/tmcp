## Compatibility promise

The public MCP tools, CLI aliases, v0.1 packet schemas, launcher contract, and
plugin manifests remain available. The release is a compatibility release
because the implementation and state-effect defaults change while those public
contracts remain stable.

## Deliberate behavior changes

- Runtime services own composition, recompile, evaluation, review,
  recommendation, promotion, receipt, artifact, explain, and session policy.
- Composition and runtime adaptation default to `cache_policy=none`; global
  cache reads and durable writes require explicit opt-in.
- `adapter=auto` remains standalone. Explicit AIOS requests fail closed for
  known sensitive values until a protected request-input protocol exists.
- Legacy `promoted-harvest.json` summaries are read-only projected into the
  current promotion-graph contract. A current `promotion-graph.json` wins when
  both representations exist; source files are never rewritten or deleted.
- Private server implementation aliases are no longer part of the test or
  compatibility surface; their runtime owners are the supported boundaries.

## Migration and rollback

Read-only consumers require no migration. Existing promotion summaries remain
readable through the cache reader. Receipts and project-local sessions have no
alternate shipped schema and remain strict readers. Hosts that cannot provide
secure descriptor-relative writes should use preview/read-only operations.

Keep the published `0.4.0` artifact available during rollout. If a consumer
requires the old state-effect defaults, pin that artifact and roll back without
rewriting local cache or receipt data.
